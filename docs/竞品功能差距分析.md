## 0. 合规边界（先划红线）

narciFarm 的定位是**设备农场管理工具**，以下能力在竞品中高频出现，但**明确不做**：

| 排除类别 | 典型功能 | 排除理由 |
|---|---|---|
| 平台运营/养号 | 自动加好友、群发消息、朋友圈批量发布、自动点赞/关注/评论/私信、直播间挂榜、批量养号 | 绕过平台风控做虚假流量；多起判例认定侵权（微信 44 功能案、抖音诉蓝海云控案） |
| 黑产级风控规避 | 一键新机/改机（IMEI/SN/MEID/Android_ID/机型伪装）、虚拟定位、代理 IP 池 | 设备指纹伪造，与"真实设备管理"定位直接冲突，法律风险最高 |
| AI 内容批量生成与多平台分发 | AI 文案/配音/剪辑、一键多平台分发、矩阵分发 | 平台运营类，非设备管理 |
| 舆情监控/用户画像 | 评论语义分析、用户画像生成 | 营销用途，超出设备农场范畴 |

> 本报告后续所有"建议补齐"的功能，均指**设备管理类**能力（ADB/Scrcpy 之上的设备编排层），与开源设备农场（STF/DeviceFarmer）能力重叠，是可正当竞争的领域。

## 2. 差距清单（按优先级）

### P0 — 核心工程能力，补齐后直接对标主流群控/自动化工具

#### ✅ P0-1 控件树与多维元素定位（最高价值）
- **现状**：只有 `tap_text` / `wait_text` / `assert_text` 按**文本**定位；`adb.py` 有 `uiautomator dump` 基础，但未暴露为步骤能力。
- **对标**：uiautomator2（text/id/class/desc/xpath/相对定位/状态选择器）、Appium（id/accessibilityId/className/uiautomator/xpath）、Poco（层级选择器）、Auto.js（完整选择器族）。
- **建议**：新增步骤 `tap_id` / `tap_desc` / `tap_xpath` / `tap_class`，并支持相对定位（`child` / `sibling` / `left` / `right`）。这是从"猜坐标"升级到"选控件"的分水岭。

#### ✅ P0-2 OCR 坐标级点击（现有 `ocr_tap` 名不副实）
- **现状**：`ocr_tap` 只校验目标文本是否出现在**整屏 OCR 结果**中，**并不点击**（`scenario.py:177-190`），既不调用 `input_tap`，也不使用 OCR 框坐标。
- **对标**：AutoX `paddle.ocr` 返回 `bounds + confidence`，可直接按识别框中心点击；按键精灵 OcrEX；Appium OCR 插件。
- **建议**：`vision.ocr_text()` 扩展为 `ocr_find(image) -> [(text, bounds, confidence), ...]`；`ocr_tap` 按识别框中心点击；支持区域 OCR 与多语言。

#### ✅ P0-3 步骤级失败重试
- **现状**：步骤失败即终止，仅自动截图取证；无 retry / backoff / 重试次数配置。
- **对标**：Maestro `retry`、SoloPi bounded retry、Airtest 的等待重试。
- **建议**：步骤支持 `retry`（次数）、`retry_interval`（退避）、`on_fail`（continue/abort/screenshot）。

#### ✅ P0-4 测试报告导出
- **现状**：运行态在内存 `_runs`，重启丢失；无 JUnit / HTML / JSON 报告，无步骤级证据归档。
- **对标**：Airtest HTML 报告、Maestro JUnit/HTML + 证据目录、SoloPi CI 可消费报告。
- **建议**：每次运行产出结构化报告（步骤、耗时、截图、断言结果、logcat 片段），支持 JUnit XML / HTML / JSON 导出。

#### ✅ P0-5 图像匹配能力增强
- **现状**：`vision.match_template()` 单模板、单尺度、单结果、固定 NCC 阈值。
- **对标**：Airtest `aircv`（模板匹配 + SIFT/SURF/ORB 特征点 + CCOEFF/RGB 置信度）、AutoX `matchTemplate(max, threshold, region, 金字塔 level)`。
- **建议**：多结果返回（`find_all`）、多尺度金字塔、匹配可视化与阈值调优 UI、特征点匹配（可选）。

### P1 — 工程化短板，决定"能不能用于正规测试团队"

#### P1-1 控件树可视化 / 元素拾取器（Inspector）
- **现状**：无 hierarchy dump 可视化、无元素拾取器。
- **对标**：Appium Inspector、UIAutoDev、PocoHierarchyViewer、Auto.js 布局分析。
- **建议**：设备详情页内嵌"控件树"面板，支持点击元素自动生成选择器。

#### ✅ P1-2 断言能力增强
- **现状**：`assert_text` / `assert_image` 只有 `exists` / `absent`。
- **对标**：Maestro `assertVisible` / `assertTrue` / `assertScreenshot`；SoloPi 节点断言 + 图片断言。
- **建议**：正则匹配、数值比较、软断言（收集所有失败再汇总）、OCR 断言、断言聚合。

#### P1-3 脚本语言 / DSL / 插件机制
- **现状**：仅 JSON 场景，无脚本语言，无插件机制。
- **对标**：Airtest Python、Appium WebDriver、AutoX JS、SoloPi 插件、CC智控开放 API（Python/Lua）。
- **建议**：提供 Python SDK（`pip install narcifarm`）或 JS DSL；开放插件机制（自定义步骤类型）。

#### ✅ P1-4 录制器增强
- **现状**：录制生成坐标点击 / 文本点击。
- **对标**：Appium Inspector Recorder、Maestro Studio、AirtestIDE。
- **建议**：控件级录制、屏幕区域截取为模板、断言录制、跨设备回放（不同分辨率自动换算）。

#### ✅ P1-5 性能监控报告化
- **现状**：agent 有 metrics / startup_time / logcat 端点，但无图表化报告。
- **对标**：SoloPi（CPU/内存/FPS/Jank/电池/温度/进程/网络流量 + 图表）、Appetizer insights.py。
- **建议**：场景运行期间采集性能指标，产出趋势图与对比报告。

#### P1-6 设备快捷操作补全
- **现状**：有批量安装/推送/Shell；部分快捷操作待补。
- **对标**：鹰眼群控（一键重启/关机/解锁/结束进程/开关飞行模式）、STF（远程亮屏定位）。
- **建议**：一键重启 / 关机 / 解锁 / 结束进程 / 飞行模式 / 亮屏定位（物理找机）。

#### P1-7 弱网模拟
- **现状**：无网络模拟能力。
- **对标**：BrowserStack / Sauce Labs / LambdaTest / Genymotion 的网络限速（3G/4G/5G/离线）。
- **建议**：通过设备侧 VPNService 或代理层实现带宽/延迟/丢包模拟。

## 3. 明确不建议对标（云手机厂商独有）

以下能力依赖 **ARM 虚拟化 / 云端流化**，自建真机农场无法复制，且与"真实设备管理"叙事冲突：

- ARM 服务器虚拟化 / 容器化多实例（华为鲲鹏、阿里倚天、百度自研 ARM、腾讯）
- 单机多路实例（华为 RX7 单机 96/160/224 路）
- 自研视频流化协议（阿里 ASP、腾讯串流加速、华为智能编码）
- 秒级弹性创建 / 在线升降配
- Android 多版本镜像任意切换
- 全球节点 / 海外云手机
- 按分钟计费体系
- 设备级克隆 / 快照（真机可做数据备份，但非虚拟磁盘快照）

> 真机农场的差异化叙事应是：**真机真实性 + 本地数据 + 私有化 + 无虚拟化指纹**。

## 6. 竞品同质化观察

1. **市场同质化极高**：除侠客、鹰眼、来喜、触动外，多数"品牌"是贴牌或营销壳，功能清单可直接按"设备管理 + 脚本 + 营销动作"三段拆解。
2. **真正的工程护城河在"设备管理类"前 5 项**（投屏、同步操作、分组、脚本、调度）——这正是开源设备农场该做深的部分。
3. **"AI Agent / 自然语言控制"是最新分化点**（侠客、达之云、阿里 Agentic Mobile、腾讯 CUA），传统群控尚未普及，是差异化机会。
4. **"跨网/广域网 + P2P + 多连接方式"** 是来喜、鹰眼、CC智控的共同卖点，narciFarm 若只支持 USB/局域网会明显落后。
5. **必须显式划红线**：把"改机/虚拟定位/代理IP/自动加好友/养号/刷量"列为 non-goal，并在文档中说明法律判例，否则会被误认为同类灰产工具。
