# narciFarm 使用手册

一台 PC 管理多台安卓设备：多路投屏、群控广播、场景编排、定时调度、批量操作。
适用场景：自有设备 + 自有/授权应用的真机测试、兼容性回归、批量安装与巡检。

> 请仅将本工具用于你拥有或获得授权的设备与应用。工具不包含、也不接受用于
> 平台刷量、账号批量注册、反检测等用途的功能。

---

## 1. 安装与启动

### 方式 A：下载现成的 exe（推荐）

到 [Releases](https://github.com/narci2018/narciFarm/releases) 下载 `narciFarm-windows-x64.exe`，放到任意目录双击运行。

- 程序未做代码签名，首次运行 Windows SmartScreen 会提示——点「更多信息 → 仍要运行」。
- 启动后约 2 秒自动打开浏览器管理台；也可手动访问 `http://127.0.0.1:8555`。
- **没有黑色控制台窗口**：程序以托盘图标形式常驻（任务栏右下角蓝色圆点 🟦）。
  - 左键/右键菜单：**打开管理台**（随时重新打开网页）、**关闭服务**；
  - 日志写入 exe 同级 `data\narciFarm.log`，排查问题看这里；
  - 若端口被占用（比如已经开着一个实例），会弹窗提示而不会静默失败。
- **不需要安装任何东西**：adb 与 scrcpy-server 已内置，Python 环境已打包。
- 数据目录在 exe 同级：`data\`（数据库与日志）、`captures\`（截图）。
- 卸载 = 退出托盘后删除 exe 与这两个目录。

### 方式 B：源码运行

前置：Python 3.10+（本机已验证 3.11）、adb 在 PATH 或已知路径。

```bat
py -3 -m pip install -r requirements.txt
py -3 -m uvicorn narci.main:app --host 127.0.0.1 --port 8555
```

或直接双击 `run.bat`。

### 命令行参数（exe 与源码入口通用）

| 参数 | 默认 | 说明 |
|---|---|---|
| `--host` | 127.0.0.1 | 监听地址；`0.0.0.0` 表示局域网可访问 |
| `--port` | 8555 | Web 端口 |
| `--no-browser` | 关 | 启动后不自动打开浏览器 |

### 如何关闭服务

- **推荐**：任务栏托盘图标右键 →「关闭服务」，服务优雅退出（自动停掉所有投屏会话与后台任务）；
- 或网页右上角「关闭服务」按钮 → 确认后退出；
- 兜底：任务管理器结束 `narciFarm.exe`，或 `taskkill /IM narciFarm.exe /F`。

> 服务关闭后网页会提示不可用；重新运行 exe（或托盘已退出时重新双击 exe）即可恢复。
> 开发者源码运行时（`py -3 main.py`）同样有托盘；`--no-tray` 可关闭托盘行为。

### 常用环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `NARCI_ADB` | 自动探测（内置 → PATH → C:\tools\platform-tools） | 指定 adb 路径 |
| `NARCI_PORT` / `NARCI_HOST` | 8555 / 127.0.0.1 | 等效命令行参数 |
| `NARCI_MAX_SIZE` | 1280 | 投屏画面长边上限，越小越省带宽 |
| `NARCI_BITRATE` | 8000000 | 投屏码率 (bps) |
| `NARCI_FPS` | 30 | 投屏帧率上限 |
| `NARCI_SNAPSHOT_INTERVAL` | 4 | 总览页快照刷新间隔（秒） |
| `NARCI_SERVER_JAR` | assets\scrcpy-server.jar | 替换 scrcpy-server 的路径 |

## 2. 接入手机

### USB 连接（推荐，延迟最低）

1. 手机进入「设置 → 关于手机」，连点「版本号」7 次开启开发者模式；
2. 「设置 → 开发者选项」打开 **USB 调试**；
3. 数据线连接 PC（选择「文件传输」模式更稳）；
4. 手机弹出「允许 USB 调试吗？」勾选「一律允许」并确定；
5. narciFarm 页面点「刷新设备」，左侧列表出现设备即成功。

状态点颜色：🟢 `device` 在线正常 · 🟡 `unauthorized` 未授权/`offline` 离线 · ⚪ `absent` 已登记但当前未连接。

### WiFi 无线连接

先插一次 USB，在 ADB 控制台执行 `tcpip 5555`，拔线后在控制台执行 `connect 手机IP:5555`；
或直接点顶栏「扫描局域网」（自动扫描并连接开放 5555 端口的设备）。

> 「扫描局域网」默认扫描 `192.168.1.0/24` 网段。若你的网段不同，可调用接口：
> `POST /api/devices/scan_lan`，请求体 `{"cidr": "192.168.50.0/24"}`。

## 3. 界面导览

- **顶栏**：adb / scrcpy-server 健康状态点、在线设备数、「刷新设备」「扫描局域网」。
- **左侧栏**：
  - 设备列表：**勾选 = 选中目标**。批量操作、群控广播、场景运行都作用于勾选设备；
  - 分组：把勾选设备加入分组，分组是「定时调度」的目标单位。
- **主区 8 个标签页**：设备总览 / 群控广播 / 批量操作 / 场景编排 / 定时调度 / ADB 控制台 / 截图库 / 日志。

## 4. 设备总览

- 每台设备一张卡片，快照按 `NARCI_SNAPSHOT_INTERVAL`（默认 4 秒）自动轮换刷新，可勾选关闭。
- **点击卡片打开投屏窗口**（见下节）。离线设备卡片半透明。

## 5. 投屏窗口（核心）

### 实时画面

- 浏览器通过 WebSocket 接收 H.264 流并用 **WebCodecs 硬解**渲染（Chrome / Edge 94+ 支持）。
- 若浏览器不支持或流建立失败，**自动降级为 1.5 秒快照轮询模式**，操作功能不受影响。

### 鼠标/触控操作

| 操作 | 效果 |
|---|---|
| 单击 | 触摸点击 |
| 按住拖动 | 滑动手势（时长按实际拖动时间） |
| 滚轮上/下 | 页面滚动 |
| 右键 | 返回键 |

### 工具栏

- **按键排**：返回 / HOME / 菜单 / 最近任务 / 电源 / 音量±（广播模式下同步发给所有目标）。
- **文本框 + 输入**：向目标设备输入文本（走 adb `input text`，见「已知限制」关于中文）。
- **存剪贴板**：把文本写入目标设备剪贴板（走 scrcpy 控制通道）。
- **截图**：当前画面存入服务端 captures 目录，可在「截图库」查看。
- **广播到选中设备** ☑：勾选后，你的每次点击/滑动/按键/文本都同步执行到「左侧勾选的全部设备」——这就是群控。坐标按每台设备自身分辨率自动换算，不同分辨率混插无影响。主控设备本身走 scrcpy 控制通道注入（低延迟），其余设备走 adb。
- **录制动作** ☑：勾选后你的每次点击/滑动/按键会作为步骤**追加到「场景编排」页的当前编辑场景**，录完去场景页保存即可复放（状态栏显示已录步数）。
- `ESC` 关闭窗口。

> **排障提示**：每次点击/滑动都会在「日志」页记录一行（指令参数、注入路径 [scrcpy]/[adb]、目标设备、坐标），
> 同时写入 exe 同级 `data\narciFarm.log`。若手机对注入"点了没反应"，先看日志里是否有
> `[serial][server] ... Could not inject ... ← 若为注入被拒...` 红色行——那是设备层面拒绝了注入，
> 多为厂商安全限制（小米需开「USB 调试（安全设置）」），与软件无关。

## 6. 群控广播页

投屏广播之外的快捷群发（作用于左侧勾选设备）：

- **主控设备 + 打开投屏窗口**：快捷打开带广播模式的投屏；
- **群发文本 / 群发按键**（HOME、返回、菜单、电源、音量、最近任务、回车）；
- **停留唤醒**：对勾选设备开启 `svc power stayon`，插着 USB 时屏幕常亮不锁屏（充电状态生效）；
- 结果框显示每台设备的执行结果。

## 7. 批量操作页

| 功能 | 用法 | 说明 |
|---|---|---|
| 批量安装 APK | 选 APK → 安装到选中设备 | 逐台上传安装，结果框显示各机输出（含失败原因） |
| 批量推送文件 | 选文件 + 远端目录 → 推送 | 默认推到远端同名路径 |
| Shell 群发 | 输入命令 → 在选中设备执行 | 并行执行，按设备分组显示输出 |
| 批量截图 | 一键对选中设备截图 | 存入「截图库」 |

## 8. 场景编排页（自动化核心）

场景 = 步骤列表 + 整场景重复次数。运行时对每台勾选设备并行执行，互不干扰。

### 步骤类型（13 种）

| 类型 | 参数 | 说明 |
|---|---|---|
| `tap` | `x_pct, y_pct` | 点击。**建议用归一化坐标 0~1**（如 0.5=屏幕中线），跨分辨率通用；也可用 `x, y` 物理像素 |
| `swipe` | `x_pct, y_pct, x2_pct, y2_pct, duration_ms` | 滑动 |
| `text` | `text` | 输入文本（`input text`，空格自动转义；中文见「已知限制」） |
| `key` | `keycode` | 按键：`back/home/menu/power/volume_up/volume_down/mute/enter/delete/tab/recents/wake/sleep` 或数字键值 |
| `back` / `home` | — | 返回 / 回主屏 |
| `launch` | `package` | 启动应用（包名，如 `com.example.myapp`） |
| `stop_app` | `package` | 强制停止应用 |
| `wait` | `ms` | 等待毫秒 |
| `shell` | `cmd, timeout` | 执行任意 shell 命令 |
| `screenshot` | `name`（可选） | 截图存入 captures |
| `tap_text` | `text` | 用 uiautomator 找到界面上该文本的控件并点它（跨分辨率更稳的点击方式） |
| `loop` | `count, steps[]` | 循环，最多嵌套 5 层 |

### 操作流程

1. **新建**场景 → 填名称 → 从下拉添加步骤 → 每步点「编辑」填参数 → 保存；
2. 也可直接编辑底部 **JSON 文本框** → 「应用 JSON → 步骤表」（嵌套 loop 建议直接写 JSON）；
3. 「导出 JSON」备份 / 「导入 JSON」恢复；
4. 左侧勾选设备 → 「在选中设备运行」；
5. 运行状态区实时显示每个设备的进度 `设备:状态(已完成步数)`，可一键「中止」。

### 示例：App 启动冒烟测试

```json
[
  { "type": "launch", "package": "com.example.myapp" },
  { "type": "wait", "ms": 3000 },
  { "type": "tap_text", "text": "设置" },
  { "type": "wait", "ms": 1000 },
  { "type": "swipe", "x_pct": 0.5, "y_pct": 0.7, "x2_pct": 0.5, "y2_pct": 0.3, "duration_ms": 300 },
  { "type": "screenshot", "name": "settings_page" },
  { "type": "back" },
  { "type": "stop_app", "package": "com.example.myapp" }
]
```

## 9. 定时调度页

- **目标必须是分组**（在左侧栏建好分组并放入设备）；
- 两种类型：
  - **间隔（秒）**：每次运行**结束后**再等 N 秒触发下一次——跑 3 分钟的场景配 3600 秒间隔 = 每 63 分钟一轮，不会重叠；
  - **每天 HH:MM**：定点触发（如 `09:30`）；
- 调度只在设备在线时执行，离线设备自动跳过并记录日志；
- 可随时启用/停用/删除；服务重启后调度从数据库恢复。

## 10. ADB 控制台 / 截图库 / 日志

- **ADB 控制台**：选设备、输入任意 shell 命令回车执行，输出带返回码。也可用来做一次性操作（如 `tcpip 5555`、`wm size`）。
- **截图库**：所有截图（批量截图/场景截图/投屏截图）缩略图墙，点击看原图。
- **日志**：服务端全量事件流（设备上下线、场景每步耗时、错误），页面常驻更新。

## 11. 典型使用流程举例

### 例 A：新版本 APK 多机回归

1. 左侧勾选全部测试机 → 批量操作页安装新 APK；
2. 场景编排新建「回归冒烟」：launch → wait → tap_text「登录」→ 输入账号（见 12 节中文限制）→ 等待 → screenshot → back；
3. 勾选设备 → 运行 → 看运行状态与日志，失败设备单独在 ADB 控制台排查。

### 例 B：演示机群日常巡检

1. 建分组「展厅机」并放入设备；
2. 场景「巡检」：home → wait → screenshot（按序号命名）→ launch 自有应用 → 等待 → screenshot；
3. 定时调度：该场景 + 「展厅机」分组 + 每天 08:00；
4. 每天看截图库与日志即可确认机器状态。

## 12. 已知限制（请务必阅读）

| 限制 | 说明 / 规避 |
|---|---|
| **中文输入** | adb `input text` 不支持非 ASCII 字符。中文内容请用投屏窗口「存剪贴板」后到设备上粘贴（输入法粘贴），或使用 `tap_text` 代替输入。后续版本计划接入 scrcpy 的 `set_clipboard(paste=true)` 自动粘贴 |
| `input text` 特殊字符 | 空格已自动转义为 `%s`；个别应用内无法接收 `input text` 事件（如部分游戏），改用 `tap_text` + 剪贴板 |
| 广播时非主控设备走 adb | 延迟约 50~200ms，且滑动动画感弱于主控；属正常现象 |
| 扫描局域网网段固定 | 默认 192.168.1.0/24，其他网段走 API 指定（见 2 节） |
| 场景编辑器嵌套 loop | UI 表格只方便编辑一层；多层嵌套直接在 JSON 文本框编写 |
| 部分厂商安全限制 | 小米「USB 安装/USB 调试（安全设置）」、华为「仅充电模式下允许 ADB」等需在开发者选项中手动打开，否则安装/注入会失败 |
| 浏览器要求 | 实时投屏需 Chrome/Edge 94+（WebCodecs）；其他浏览器自动退化为快照模式 |

## 13. 常见问题排查

| 现象 | 排查顺序 |
|---|---|
| 设备不出现在列表 | 换数据线/USB 口 → 手机上重插并看授权弹窗 → 控制台 `adb devices` 是否列出 → 顶栏 adb 状态点是否绿色 |
| 设备黄色 `unauthorized` | 手机解锁屏幕，重新插拔，点掉「允许 USB 调试」弹窗 |
| 安装 APK 失败 | 看结果框错误码：`INSTALL_FAILED_USER_RESTRICTED`=小米需开「USB 安装」并允许弹窗；`INSTALL_FAILED_ALREADY_EXISTS` 签名冲突需先卸载 |
| 投屏黑屏/失败 | 日志页看 server 输出；多屏设备可在控制台查 `dumpsys display`；浏览器换 Chrome/Edge；或直接用快照模式继续操作 |
| 点击没反应 | 确认没开「广播到选中设备」而勾选列表为空（此时只有主控响应）；部分系统弹窗（MIUI 安装确认）拒绝模拟点击，需人工确认 |
| 场景某步报错停止 | 该设备状态变 `error` 并在日志显示原因，其余设备继续跑 |
| 端口被占用 | `--port 8560` 换端口，或环境变量 `NARCI_PORT` |
| exe 报毒/SmartScreen | 未签名的正常提示，加白名单即可 |

## 14. 二次开发速查（REST API）

| 端点 | 说明 |
|---|---|
| `GET /api/devices?refresh=true` | 设备列表（含状态、分辨率、分组） |
| `POST /api/devices/{serial}/shell` `{cmd}` | 执行 shell |
| `POST /api/devices/{serial}/input` `{action,params}` | tap/swipe/text/key |
| `POST /api/devices/{serial}/screenshot` | 截图并入库 |
| `POST /api/devices/{serial}/install` (multipart `apk`) | 安装 |
| `POST /api/broadcast` `{action,params,targets}` | 群控输入 |
| `GET/POST/PUT/DELETE /api/scenarios[...]` | 场景 CRUD；`POST /api/scenarios/{id}/run` 运行 |
| `GET /api/runs` + `POST /api/runs/{id}/abort` | 运行状态 / 中止 |
| `GET/POST/PUT/DELETE /api/schedules[...]` | 调度 CRUD |
| `WS /ws/mirror/{serial}` | 视频流（二进制帧）+ 注入（JSON 文本） |
| `WS /ws/events` | 服务事件流 |

交互式 WebSocket 命令格式（JSON 文本帧）：`{"action":"tap","nx":0.5,"ny":0.3,"targets":["serial1"]}`、
`{"action":"swipe","nx1":...,"ny1":...,"nx2":...,"ny2":...,"duration_ms":200}`、
`{"action":"key","keycode":"back"}`、`{"action":"text","text":"..."}`、`{"action":"set_clipboard","text":"..."}`。

## 15. 版本发布流程

```bash
git tag v0.1.1
git push origin main v0.1.1
```

CI 自动打包 exe 与 scrcpy-server 并挂到对应 Release（详见 README「构建与发布」）。
若 tag 推送后 Actions 未触发，删掉重推该 tag 即可。
