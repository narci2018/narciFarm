# narciFarm 使用手册

一台 PC 管理多台安卓设备：多路投屏、群控广播、场景编排、定时调度、批量操作。
适用场景：自有设备 + 自有/授权应用的真机测试、兼容性回归、批量安装与巡检。

> 请仅将本工具用于你拥有或获得授权的设备与应用。工具不包含、也不接受用于
> 平台刷量、账号批量注册、反检测等用途的功能。

---

## 1. 安装与启动

### 方式 A：下载现成的 exe（推荐）

到 [Releases](https://github.com/narci2018/narciFarm/releases) 下载 `narciFarm-windows-x64.exe`，放到任意目录双击运行。

- 程序未做代码签名，首次运行 Windows SmartScreen 会提示——点「更多信息 → 仍要运行」。
- 启动后约 2 秒自动打开浏览器管理台；也可手动访问 `http://127.0.0.1:8555`。
- **没有黑色控制台窗口**：程序以托盘图标形式常驻（任务栏右下角蓝色圆点 🟦）。
  - 左键/右键菜单：**打开管理台**（随时重新打开网页）、**关闭服务**；
  - 日志写入 exe 同级 `data\narciFarm.log`，排查问题看这里；
  - 若端口被占用（比如已经开着一个实例），会弹窗提示而不会静默失败。
- **不需要安装任何东西**：adb 与 scrcpy-server 已内置，Python 环境已打包。
- 数据目录在 exe 同级：`data\`（数据库与日志）、`captures\`（截图）。
- 卸载 = 退出托盘后删除 exe 与这两个目录。

### 方式 B：源码运行

前置：Python 3.10+（本机已验证 3.11）、adb 在 PATH 或已知路径。

```bat
py -3 -m pip install -r requirements.txt
py -3 -m uvicorn narci.main:app --host 127.0.0.1 --port 8555
```

或直接双击 `run.bat`。

### 命令行参数（exe 与源码入口通用）

| 参数 | 默认 | 说明 |
|---|---|---|
| `--host` | 127.0.0.1 | 监听地址；`0.0.0.0` 表示局域网可访问 |
| `--port` | 8555 | Web 端口 |
| `--no-browser` | 关 | 启动后不自动打开浏览器 |

### 如何关闭服务

- **推荐**：任务栏托盘图标右键 →「关闭服务」，服务优雅退出（自动停掉所有投屏会话与后台任务）；
- 或网页右上角「关闭服务」按钮 → 确认后退出；
- 兜底：任务管理器结束 `narciFarm.exe`，或 `taskkill /IM narciFarm.exe /F`。

> 服务关闭后网页会提示不可用；重新运行 exe（或托盘已退出时重新双击 exe）即可恢复。
> 任何关闭请求都会启动 10 秒看门狗：优雅停机未完成则强制退出（日志记录 `强制退出进程`）。
> 开发者源码运行时（`py -3 main.py`）同样有托盘；`--no-tray` 可关闭托盘行为。

### 常用环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `NARCI_ADB` | 自动探测（内置 → PATH → C:\tools\platform-tools） | 指定 adb 路径 |
| `NARCI_PORT` / `NARCI_HOST` | 8555 / 127.0.0.1 | 等效命令行参数 |
| `NARCI_MAX_SIZE` | 1280 | 投屏画面长边上限，越小越省带宽 |
| `NARCI_BITRATE` | 8000000 | 投屏码率 (bps) |
| `NARCI_FPS` | 30 | 投屏帧率上限 |
| `NARCI_SNAPSHOT_INTERVAL` | 4 | 总览页快照刷新间隔（秒） |
| `NARCI_SERVER_JAR` | assets\scrcpy-server.jar | 替换 scrcpy-server 的路径 |

## 2. 接入手机

### USB 连接（推荐，延迟最低）

1. 手机进入「设置 → 关于手机」，连点「版本号」7 次开启开发者模式；
2. 「设置 → 开发者选项」打开 **USB 调试**；
3. 数据线连接 PC（选择「文件传输」模式更稳）；
4. 手机弹出「允许 USB 调试吗？」勾选「一律允许」并确定；
5. narciFarm 页面点「刷新设备」，左侧列表出现设备即成功。

状态点颜色：🟢 `device` 在线正常 · 🟡 `unauthorized` 未授权/`offline` 离线 · ⚪ `absent` 已登记但当前未连接。

### WiFi 无线连接

先插一次 USB，在 ADB 控制台执行 `tcpip 5555`，拔线后在控制台执行 `connect 手机IP:5555`；
或直接点顶栏「扫描局域网」（自动扫描并连接开放 5555 端口的设备）。

> 「扫描局域网」默认扫描 `192.168.1.0/24` 网段。若你的网段不同，可调用接口：
> `POST /api/devices/scan_lan`，请求体 `{"cidr": "192.168.50.0/24"}`。

## 4. 设备总览

- 每台设备一张卡片，快照按 `NARCI_SNAPSHOT_INTERVAL`（默认 4 秒）自动轮换刷新，可勾选关闭。
- **点击卡片打开投屏窗口**（见下节）。离线设备卡片半透明。

## 5. 投屏窗口（核心）

### 实时画面

- 浏览器通过 WebSocket 接收 H.264 流并用 **WebCodecs 硬解**渲染（Chrome / Edge 94+ 支持）。
- 若浏览器不支持或流建立失败，**自动降级为 1.5 秒快照轮询模式**，操作功能不受影响。
- **连接过程有遮罩提示**：旋转指示 + “已等待 X.Xs” 秒表 + 【取消】按钮，不再“黑屏干等”；
  若耗时异常，请查「日志」页的 `投屏启动耗时` 分阶段记录（jar推送/端口转发/server进程/隧道连接/读流就绪/首帧到达），把该行发给我们即可定位瓶颈。

### 窗口操作

- **移动**：按住顶部标题栏拖动；**缩放**：拖动窗口右下角（原生 resize，最小 380×260）。

### 鼠标/触控操作

| 操作 | 效果 |
|---|---|
| 单击 | 触摸点击 |
| 按住拖动 | 滑动手势（时长按实际拖动时间） |
| 滚轮上/下 | 页面滚动 |
| 右键 | 返回键 |

### 工具栏

- **按键排**：唤醒 / 返回 / HOME / 菜单 / 最近任务 / 电源 / 音量±（广播模式下同步发给所有目标）。手机熄屏时**首次操作会自动发送唤醒键**并在投屏状态条橙色提示（日志同步记录）；若停在锁屏仍需在手机上手动解锁；
- **文本框 + 输入**：向目标设备输入文本（走 adb `input text`，仅 ASCII；含中文会自动改走剪贴板粘贴路径）；
- **粘贴**：把输入框内容（为空时取 PC 剪贴板）写入手机剪贴板并**立即执行粘贴**——这是输入中文的推荐方式，需手机焦点在输入框内、且处于实时投屏模式；
- **存剪贴板**：仅写入设备剪贴板，不粘贴；
- **⏺ 录像**：把投屏画面录成 webm 下载（再次点击停止）；
- **截图**：当前画面存入服务端 captures 目录，可在「截图库」查看。
- **广播到选中设备** ☑：勾选后，你的每次点击/滑动/按键/文本都同步执行到「左侧勾选的全部设备」——这就是群控。坐标按每台设备自身分辨率自动换算，不同分辨率混插无影响。主控设备本身走 scrcpy 控制通道注入（低延迟），其余设备走 adb。
- **录制动作** ☑：勾选后你的每次点击/滑动/按键会作为步骤**追加到「场景编排」页的当前编辑场景**，录完去场景页保存即可复放（状态栏显示已录步数）。
- `ESC` 关闭窗口。

> **排障提示**：每次点击/滑动都会在「日志」页记录一行（指令参数、注入路径 [scrcpy]/[adb]、目标设备、坐标），
> 同时写入 exe 同级 `data\narciFarm.log`。若手机对注入"点了没反应"，先看日志里是否有
> `[serial][server] ... Could not inject ... ← 若为注入被拒...` 红色行——那是设备层面拒绝了注入，
> 多为厂商安全限制（小米需开「USB 调试（安全设置）」），与软件无关。
>
> 若投屏里点击后**日志页完全没有注入行**（连失败都没有），看同一页的 `[前端诊断] press` 行：
> 它记录了浏览器是否真的产生了按下事件、画布尺寸/位置与浏览器 UA。这一行存在说明浏览器侧正常、
> 问题在服务端；这一行不存在说明点击没落在画布上（刷新页面 Ctrl+F5 获取新版前端后再试）。

## 6. 群控广播页

投屏广播之外的快捷群发（作用于左侧勾选设备）：

- **主控设备 + 打开投屏窗口**：快捷打开带广播模式的投屏；
- **群发文本 / 群发按键**（HOME、返回、菜单、电源、音量、最近任务、回车）；
- **停留唤醒**：对勾选设备开启 `svc power stayon`，插着 USB 时屏幕常亮不锁屏（充电状态生效）；
- 结果框显示每台设备的执行结果。

## 7. 批量操作页

批量页除安装/推送/Shell 群发/截图外，还有两块：

**设备快捷操作**：对选中设备执行 找机（亮屏）/ 锁屏 / 解锁 / 开飞行模式 / 关飞行模式 / 重启 / 关机 / 保持唤醒，以及按包名「结束应用」「清除数据」。
危险动作（关机、清除数据、重启）会先弹确认。

**弱网模拟**：把选中设备的全局 HTTP 代理指向本机节流代理，模拟窄带（`带宽 kbps`）、高延迟（`延迟 ms`）与丢包（`丢包 %`）。
只影响经过代理的流量；HTTPS 走隧道限速（不做中间人解密）。随时点「关闭弱网」恢复。

| 功能 | 用法 | 说明 |
|---|---|---|
| 批量安装 APK | 选 APK → 安装到选中设备 | 逐台上传安装，结果框显示各机输出（含失败原因） |
| 批量推送文件 | 选文件 + 远端目录 → 推送 | 默认推到远端同名路径 |
| Shell 群发 | 输入命令 → 在选中设备执行 | 并行执行，按设备分组显示输出 |
| 批量截图 | 一键对选中设备截图 | 存入「截图库」 |

## 8. 场景编排页（自动化核心）

场景 = 步骤列表 + 整场景重复次数。运行时对每台勾选设备并行执行，互不干扰。

### 步骤类型（20 种）

| 类型 | 参数 | 说明 |
|---|---|---|
| `tap` | `x_pct, y_pct` | 点击。**建议用归一化坐标 0~1**（如 0.5=屏幕中线），跨分辨率通用；也可用 `x, y` 物理像素 |
| `swipe` | `x_pct, y_pct, x2_pct, y2_pct, duration_ms` | 滑动 |
| `text` | `text` | 输入文本（`input text`，空格自动转义；中文见「已知限制」） |
| `key` | `keycode` | 按键：`back/home/menu/power/volume_up/volume_down/mute/enter/delete/tab/recents/wake/sleep` 或数字键值 |
| `back` / `home` | — | 返回 / 回主屏 |
| `launch` | `package` | 启动应用（包名，如 `com.example.myapp`） |
| `stop_app` | `package` | 强制停止应用 |
| `wait` | `ms` | 等待毫秒 |
| `shell` | `cmd, timeout` | 执行任意 shell 命令 |
| `screenshot` | `name`（可选） | 截图存入 captures |
| `tap_text` | `text` | 用 uiautomator 找到界面上该文本的控件并点它（跨分辨率更稳的点击方式） |
| `wait_text` | `text, timeout_ms, interval_ms` | 轮询等待文本出现，超时则该设备判失败 |
| `assert_text` | `text, expect` | 断言文本 `exists`（须存在）/ `absent`（须不存在），用于验证界面状态 |
| `assert_value` | `actual, expected, op` | 数值/变量比较断言，`op` 支持 `eq/ne/gt/gte/lt/lte/contains/regex`（`actual` 支持 `{{变量}}`） |
| `rand_wait` | `min_ms, max_ms` | 区间内随机等待 |
| `start_activity` | `component` | 直接拉起 Activity（如 `com.example/.MainActivity`） |
| `reboot` | `wait` | 重启设备；`wait: true` 时阻塞直到设备重新上线 |
| `locate` | — | 找机：唤醒 + 拉满亮度 + 解锁，便于在机架上定位 |
| `airplane` | `on` | 开关飞行模式 |
| `lock` / `unlock` | — | 锁屏 / 唤醒并尝试解锁（仅限无密码锁屏） |
| `loop` | `count, steps[]` | 循环，最多嵌套 5 层 |
| `tap_image` | `image, threshold` | 图像模板匹配点击（NCC，跨分辨率可用） |
| `wait_image` | `image, timeout_ms, interval_ms, threshold` | 轮询等待图像出现 |
| `assert_image` | `image, expect, threshold` | 断言图像存在/不存在 |
| `find_image` | `image, threshold, max_results, region, scales` | **多结果**图像匹配，返回每个匹配的中心坐标与得分 |
| `ocr_tap` | `text, region` | OCR 找到文字后**点击其识别框中心**（需 Tesseract） |
| `ocr_get` | `text` | 取屏幕 OCR 文本 |
| `ocr_find` | `text, region` | OCR 坐标查找，返回文字 + 边界框 + 置信度 |
| `tap_el` | `kind, value, contains, index` | **控件定位点击**：按 text/id/desc/class/package/xpath 找控件并点其中心 |
| `wait_el` | 同上 + `timeout_ms, interval_ms` | 轮询等待控件出现 |
| `assert_el` | 同上 + `expect` | 断言控件存在/不存在 |
| `swipe_el` | 同上 + `x2, y2, duration_ms` | 从控件中心起滑动 |

> 场景步骤失败时**自动截图**存入 `captures\auto\`，失败现场可回溯。

#### 失败重试策略（所有步骤通用）

每个步骤都可以带三个可选参数，用于应对弹窗、动画、网络抖动等瞬时失败：

| 参数 | 默认 | 说明 |
|---|---|---|
| `retry` | `0` | 失败后的重试次数 |
| `retry_interval_ms` | `500` | 每次重试前的等待（退避间隔） |
| `on_fail` | `abort` | 重试全部失败后：`abort` 终止该设备运行（默认）／`continue` 记录跳过并继续下一步 |

示例——等待某个异步加载的控件，最多重试 3 次、每次间隔 1 秒：

```json
{ "type": "wait_el", "kind": "id", "value": "com.example:id/submit_btn",
  "timeout_ms": 2000, "retry": 3, "retry_interval_ms": 1000 }
```

#### 断言匹配模式与软断言

`assert_text` / `assert_el` 支持 `match` 参数：

| match | 含义 |
|---|---|
| `exact` | 完全相等 |
| `contains` | 包含子串（**默认**，兼容旧场景） |
| `regex` | 正则匹配 |
| `startswith` / `endswith` | 前缀 / 后缀 |

所有断言步骤都支持 `soft: true` —— **软断言**：失败时记录到报告但**不中止**该设备的后续步骤，
适合一次性收集多处问题（例如同时校验多个字段）。软断言失败仍会让报告判为失败，CI 能拦住。

#### 控件定位维度（`kind`）

| kind | 对应 uiautomator 属性 | 示例 |
|---|---|---|
| `text` | `text` | `"设置"` |
| `id` | `resource-id` | `"com.example:id/login"` |
| `desc` | `content-desc` | `"确定"` |
| `class` | `class` | `"android.widget.Button"` |
| `package` | `package` | `"com.example"` |
| `xpath` | — | `".//node[@text='取消']"`（支持 ElementTree 子集） |

配合 `contains: true` 可做模糊包含匹配；`index` 用于多个匹配时取第几个（从 0 起）。

### 操作流程

1. **新建**场景 → 填名称 → 从下拉添加步骤 → 每步点「编辑」填参数 → 保存；
2. 也可直接编辑底部 **JSON 文本框** → 「应用 JSON → 步骤表」（嵌套 loop 建议直接写 JSON）；
3. 「导出 JSON」备份 / 「导入 JSON」恢复；
4. 左侧勾选设备 → 「在选中设备运行」；
5. 运行状态区实时显示每个设备的进度 `设备:状态(已完成步数)`，可一键「中止」。

### 示例：App 启动冒烟测试

```json
[
  { "type": "launch", "package": "com.example.myapp" },
  { "type": "wait", "ms": 3000 },
  { "type": "tap_text", "text": "设置" },
  { "type": "wait", "ms": 1000 },
  { "type": "swipe", "x_pct": 0.5, "y_pct": 0.7, "x2_pct": 0.5, "y2_pct": 0.3, "duration_ms": 300 },
  { "type": "screenshot", "name": "settings_page" },
  { "type": "back" },
  { "type": "stop_app", "package": "com.example.myapp" }
]
```

## 8.1 测试报告页

场景运行结束后会**自动生成报告**并落盘到 `reports/`，服务重启不丢失。

- **列表**：场景名、状态（✅ 通过 / ❌ 失败 / ⏳ 运行中）、设备数、步骤数、失败数、耗时、生成时间；
- **查看**：展开每台设备的步骤明细（步骤类型、耗时、返回值/错误、失败取证截图路径）；
- **导出**：
  - `HTML` —— 自包含网页报告，可直接归档或邮件发送；
  - `JUnit` —— 标准 JUnit XML，可接入 Jenkins / GitLab CI / GitHub Actions 的测试结果面板；
  - JSON —— 通过 `GET /api/reports/{id}` 取原始数据，便于二次处理。

> 报告里只包含**设备与步骤执行结果**，不包含任何账号、内容分发或平台运营数据。

## 8.3 录制器增强

投屏窗口勾选「录制动作」后，录制生成的步骤会自动升级，并提供三个新工具：

- **控件级录制**：点击步骤在写入场景时，会同步解析该坐标对应的控件（优先 resource-id，其次 content-desc / 文本 / 类名），
  自动改写为 `tap_el` 控件定位步骤。这样录制的场景**跨分辨率可回放**，不会因为换机型而点错位置。
- **▣ 框选模板**：点击后进入框选模式，在画面上拖出矩形区域，松手即把该区域存为图像模板（出现在场景页的模板列表），
  可直接用于 `tap_image` / `assert_image` 步骤。
- **✔ 断言 / 📷 截图**：录制过程中随时向场景插入文本断言步骤或截图步骤，无需切回场景页。

「开发工具」页新增两块面板，用于手动排查与生成场景步骤：

- **控件树 / 元素定位**：选设备 → 选维度（text/id/desc/class/package/xpath）→ 填匹配值 → 「查找」。结果表格列出文本、资源 ID、类名、中心坐标、是否可点，点「点击」可直接驱动该设备（等价于 `tap_el`）。「刷新控件树」返回当前界面的完整节点列表。
- **OCR 坐标识别**：选设备 → 可选填过滤文字 → 「识别屏幕」。返回每个识别词的边界框、中心点与置信度，点「点击」即按识别框中心点击（等价于 `ocr_tap`）。

这两块面板是**只读排查工具**，不会向设备写入任何数据，也不涉及账号或平台操作。

## 8.4 步骤插件（扩展步骤类型）

内置步骤满足不了时，可以用 Python 插件扩展新的步骤类型，无需改动主程序。

1. 在插件目录（默认 `<数据目录>/plugins`，可由 `NARCI_PLUGINS_DIR` 指定）新建 `my_steps.py`；
2. 文件里实现一个 `register(reg)`，用 `reg.step(类型名, 处理器)` 登记；
3. 处理器签名为 `async def run(step, serial, size, run_id) -> dict`；
4. 重启服务——「开发工具 → 步骤插件」会列出已注册的类型，场景步骤里可直接使用。

参考 `examples/plugins/01_demo_steps.py`。插件**只在内置类型不匹配时生效**，因此不会覆盖原有行为。

```python
from narci import adb

async def run_click_center(step, serial, size, run_id):
    w, h = size or (0, 0)
    await adb.input_tap(serial, w // 2, h // 2)
    return {"x": w // 2, "y": h // 2}

def register(reg):
    reg.step("click_center", run_click_center, description="点击屏幕中心")
```

## 8.5 Python SDK

`client/` 目录是可独立安装的 Python 客户端（`pip install ./client`），用于在 CI 或脚本里驱动设备农场：

- 登录 / 设备枚举 / 控件树 / 元素查找 / 性能指标 / 批量输入；
- 场景创建与运行、运行状态轮询、中止；
- 报告查询与 HTML / JUnit 导出。

```python
from narcifarm import Client

with Client("http://127.0.0.1:8555") as c:
    c.login("admin", "admin")
    run_id = c.run_scenario([{"type": "wait", "ms": 500}],
                              targets=[d["serial"] for d in c.devices()])
    report = c.wait_report(run_id)
    print(report["status"])
```

完整 API 见 `client/README.md`。

## 9. 定时调度页

- **目标必须是分组**（在左侧栏建好分组并放入设备）；
- 两种类型：
  - **间隔（秒）**：每次运行**结束后**再等 N 秒触发下一次——跑 3 分钟的场景配 3600 秒间隔 = 每 63 分钟一轮，不会重叠；
  - **每天 HH:MM**：定点触发（如 `09:30`）；
- 调度只在设备在线时执行，离线设备自动跳过并记录日志；
- 可随时启用/停用/删除；服务重启后调度从数据库恢复。

## 9.1 设备托管（Device Owner）

让设备进入受管状态后可做：锁定为单应用 Kiosk、禁止恢复出厂、远程锁屏/擦除、限制相机与截屏。
**前提**：设备上要有一个 DPC（设备策略控制器）应用，并设为 Device Owner。

1. 用 `dpc/` 目录里的参考 DPC 构建并安装（或装 Google 的 TestDPC）：

```bash
cd dpc/narci_dpc && ./gradlew assembleDebug
adb install app/build/outputs/apk/debug/app-debug.apk
adb shell dpm set-device-owner io.narcifarm.dpc/.NarciDeviceAdminReceiver
```

2. 在「批量操作 → 设备托管」面板填组件名点「设置」（也可手动执行上面的 dpm 命令）；
3. 点「读取托管状态」确认 `已托管`，再下发策略命令。

> 设备需**已恢复出厂、未登录账号、未设置过 Device Owner**才能设置成功。
> 远程擦除不可恢复，面板会先弹确认。
>
> 面板还支持下发 **Wi-Fi 配置**（Device Owner 免用户确认）、**始终开启 VPN**、
> 以及**安装 CA 证书**（先上传证书文件，由 DPC 装到系统信任库）。

## 10. 应用管理

- **应用管理**：选设备加载第三方应用列表（可搜索），支持启动 / 停止 / 卸载；
- **ADB 控制台**：选设备、输入任意 shell 命令回车执行，输出带返回码。也可用来做一次性操作（如 `tcpip 5555`、`wm size`）；
- **截图库**：所有截图（批量截图/场景截图/投屏截图）缩略图墙，点击看原图；
- **日志**：服务端全量事件流（设备上下线、场景每步耗时、错误），页面常驻更新。

> WiFi 设备会自动重连：注册表里的无线设备掉线后，服务每 60 秒自动尝试 `adb connect`，无需人工干预。

## 12. 已知限制（请务必阅读）

| 限制 | 说明 / 规避 |
|---|---|
| **中文输入** | adb `input text` 不支持非 ASCII。推荐路径：投屏窗口「粘贴」按钮（输入框填文本或复制到 PC 剪贴板 → 写入设备剪贴板并立即粘贴，需焦点在输入框 + 实时投屏模式）；「输入」按钮对含中文文本会自动改走此路径 |
| `input text` 特殊字符 | 空格已自动转义为 `%s`；个别应用内无法接收 `input text` 事件（如部分游戏），改用 `tap_text` + 剪贴板 |
| 广播时非主控设备走 adb | 延迟约 50~200ms，且滑动动画感弱于主控；属正常现象 |
| 扫描局域网网段固定 | 默认 192.168.1.0/24，其他网段走 API 指定（见 2 节） |
| 场景编辑器嵌套 loop | UI 表格只方便编辑一层；多层嵌套直接在 JSON 文本框编写 |
| 部分厂商安全限制 | 小米「USB 安装/USB 调试（安全设置）」、华为「仅充电模式下允许 ADB」等需在开发者选项中手动打开，否则安装/注入会失败 |
| 浏览器要求 | 实时投屏需 Chrome/Edge 94+（WebCodecs）；其他浏览器自动退化为快照模式 |
| 控件树 dump | `uiautomator dump` 在部分系统界面（如锁屏、部分游戏/输入法）会返回空或报错，此时改用坐标点击或图像匹配 |
| OCR 依赖 | 需系统安装 Tesseract 及中文语言包；未安装时 `ocr_*` 步骤会返回空结果而非报错 |

## 13. 常见问题排查

| 现象 | 排查顺序 |
|---|---|
| 设备不出现在列表 | 换数据线/USB 口 → 手机上重插并看授权弹窗 → 控制台 `adb devices` 是否列出 → 顶栏 adb 状态点是否绿色 |
| 设备黄色 `unauthorized` | 手机解锁屏幕，重新插拔，点掉「允许 USB 调试」弹窗 |
| 安装 APK 失败 | 看结果框错误码：`INSTALL_FAILED_USER_RESTRICTED`=小米需开「USB 安装」并允许弹窗；`INSTALL_FAILED_ALREADY_EXISTS` 签名冲突需先卸载 |
| 投屏黑屏/失败 | 日志页看 server 输出；多屏设备可在控制台查 `dumpsys display`；浏览器换 Chrome/Edge；或直接用快照模式继续操作 |
| 点击没反应 | 确认没开「广播到选中设备」而勾选列表为空（此时只有主控响应）；部分系统弹窗（MIUI 安装确认）拒绝模拟点击，需人工确认 |
| 场景某步报错停止 | 该设备状态变 `error` 并在日志显示原因，其余设备继续跑 |
| 端口被占用 | `--port 8560` 换端口，或环境变量 `NARCI_PORT` |
| exe 报毒/SmartScreen | 未签名的正常提示，加白名单即可 |

## 14. 二次开发速查（REST API）

| 端点 | 说明 |
|---|---|
| `GET /api/devices?refresh=true` | 设备列表（含状态、分辨率、分组） |
| `POST /api/devices/{serial}/shell` `{cmd}` | 执行 shell |
| `POST /api/devices/{serial}/input` `{action,params}` | tap/swipe/text/key |
| `POST /api/devices/{serial}/screenshot` | 截图并入库 |
| `POST /api/devices/{serial}/install` (multipart `apk`) | 安装 |
| `POST /api/broadcast` `{action,params,targets}` | 群控输入 |
| `GET/POST/PUT/DELETE /api/scenarios[...]` | 场景 CRUD；`POST /api/scenarios/{id}/run` 运行 |
| `GET /api/runs` + `POST /api/runs/{id}/abort` | 运行状态 / 中止 |
| `GET /api/reports` | 报告列表（摘要） |
| `GET /api/reports/{id}` | 报告原始 JSON |
| `GET /api/reports/{id}.html` / `.xml` | HTML 报告 / JUnit XML |
| `DELETE /api/reports/{id}` | 删除报告（管理员） |
| `GET /api/devices/{serial}/hierarchy` | 当前界面控件树（扁平节点列表） |
| `GET /api/devices/{serial}/elements?kind=&value=&contains=` | 按维度查找控件 |
| `POST /api/devices/{serial}/ocr` `{target?,region?}` | OCR 坐标识别 |
| `POST /api/devices/{serial}/match-image` `{image,threshold,max_results,region?,scales?}` | 多结果/多尺度图像匹配 |
| `GET/POST/PUT/DELETE /api/schedules[...]` | 调度 CRUD |
| `WS /ws/mirror/{serial}` | 视频流（二进制帧）+ 注入（JSON 文本） |
| `WS /ws/events` | 服务事件流 |

交互式 WebSocket 命令格式（JSON 文本帧）：`{"action":"tap","nx":0.5,"ny":0.3,"targets":["serial1"]}`、
`{"action":"swipe","nx1":...,"ny1":...,"nx2":...,"ny2":...,"duration_ms":200}`、
`{"action":"key","keycode":"back"}`、`{"action":"text","text":"..."}`、`{"action":"set_clipboard","text":"..."}`。
